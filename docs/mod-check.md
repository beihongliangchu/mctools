# Minecraft 模组依赖检查工具 · 使用说明

**mod-check v1.0**

## 这是什么

一个专门检查 mods 文件夹的工具。

整合包崩溃的原因，一半以上出在 mods 文件夹里。但这个文件夹从外面看就是一堆 jar，看不出谁缺了前置、谁装了两遍、谁跟游戏版本对不上。

这个工具会把每个 jar 拆开，读里面的元数据，然后告诉你：

- 缺了哪个前置模组
- 同一个模组装了几个版本
- 哪些 jar 已经损坏、打不开
- 哪些模组要求的游戏版本和你的实例对不上
- Fabric 和 Forge 模组是不是混在一起了

它只读文件，不会修改、移动或删除 mods 里的任何东西。

## 怎么用

最简单：把 `mods` 文件夹（或者整合包实例文件夹）拖到 `mod-check.bat` 上松手。

也可以直接双击，它会自己去找常见的 mods 位置。

整合包大的话要等一会儿（几百个 jar 大概一两分钟），窗口里会显示进度。

## 报告在哪

工具旁边会生成两个文件：

```
mod-check-report.txt     给人看的报告
mod-check-report.json    给"诊断报告生成器"用的数据
```

## 报告里有什么

**一、结论** —— 分三档，每条都带"依据"（具体是哪几个文件）和"怎么办"：

| 标记 | 含义 |
|---|---|
| `[确定]` | 就是这个问题 |
| `[可能]` | 对得上，但要看情况 |
| `[提示]` | 顺带提一句 |

**二、模组文件夹概览** —— jar 总数、解析成功几个、打不开几个，以及这个实例用的是 Fabric 还是 Forge。

**三、完整模组清单**（加 `-ShowAll` 才有）

**四、下一步怎么做**

## 几种最常见的模组问题

**1. 缺前置**

报告里写"缺少 N 个前置模组"，并列出被谁需要。前置就是"别的模组要用到的东西"，不装就起不来。

| 加载器 | 常见前置 |
|---|---|
| Fabric | Fabric API、Cloth Config、Architectury API、Mod Menu |
| Forge | Bookshelf、Placebo、Mantle、Curios、GeckoLib |

> Fabric API 的内部 id 叫 `fabric`，不是 `fabric-api`，这是正常的。

**2. 重复模组**

同一个模组装了两个版本（比如 `create-0.5.1.jar` 和 `create-0.5.2.jar`）。加载器会报 `Duplicate mods` 然后直接崩。删掉旧的那个。

**3. jar 损坏**

打不开的 jar。多半是下载没下完，或者被杀毒软件隔离过。重新下一遍就行。

**4. 游戏版本对不上**

比如模组要求 1.20.1，你的实例是 1.19.2。去模组发布页下载对应版本的那一版。

**5. 加载器混用**

Fabric 模组和 Forge 模组混在一个文件夹里。这条是"提示"级别，因为有些前置库会把两种元数据都带上，不一定是错的。

## 怎么把结果发给我

闲鱼聊天窗口不能发文件，所以工具会自动帮你准备两样东西：

```
发给客服.txt     一段文字摘要
发给客服.png     一张结果卡片
```

分析完之后：

- **方法一**：工具已经帮你把文字复制好了。直接切到闲鱼聊天窗口，按 `Ctrl+V` 粘贴发送。
- **方法二**：工具会自动打开它所在的文件夹，把里面那张 `发给客服.png` 拖进聊天窗口发送。

两个都发一份也行，我看得越快。

图片里只写整合包的名字，不会带上你电脑的完整路径。

## 常见问题

**Q：报告说"没有发现问题"，但游戏还是崩？**
A：说明 mods 文件夹本身是干净的。问题在别处，用 `crash-doctor` 看崩溃日志。

**Q：有些 jar 显示"无 modId"或者"coremod 或前置库"？**
A：正常。有些库类 jar 不带标准元数据，工具认不出它的名字，但这不代表它有问题。

**Q：解析花的时间是不是太久？**
A：几百个模组确实要等一两分钟。每个 jar 都要打开读一次元数据，这是必须的。窗口里有进度，没卡死。

**Q：会不会把我 mods 里的东西弄坏？**
A：不会。全程只读，一个字节都不写。报告是另外新建的文件。

## 注意事项

- 动 mods 之前，先把整个 mods 文件夹复制一份备份。
- 一次只改一样东西，改完就启动试一次。一次删五个模组，出问题就不知道是哪个引起的了。
- 不要一边看这个工具一边手动改，改完重新跑一次确认干净了再启动。
