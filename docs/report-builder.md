# Minecraft 诊断交付报告生成器 · 使用说明

**report-builder v1.0**

> ⚠️ 这个不是给客户用的，是**你自己用的**。

## 这是什么

前面三个工具（`crash-doctor` / `java-doctor` / `mod-check`）跑完之后，各自会生成一个 `.json` 数据文件。这个工具把那些 json 汇总起来，生成一份**排版好的 HTML 报告**，可以直接发给客户。

这份报告就是你收那笔钱的理由：客户拿到的不是"聊了几句、对方说搞定了"，而是一份写着问题、依据、处理步骤的正式报告。

## 为什么要有它

闲鱼上常见的情况是：客户拖着不点确认收货，甚至直接逃单。

拖延和逃单，根子是同一个 —— **客户手里没有一个"我拿到了什么"的凭证。**

只有口头结论的时候：

- 他不知道自己是不是真的解决了
- 遇到问题他也没东西可以拿去质询
- 客单价这么低，他觉得不值当较真，直接消失最省事

有了这份报告：

- 交付物从"聊了几句"变成"一个文件"
- 他手里有东西了，反而不容易跑
- **你有了涨价的依据** —— 同样的活，从"帮你看看"变成"给你一份诊断报告"

顺带一提：报告脱敏之后可以直接发小红书、贴吧、QQ 群，它本身就是证明"这人专业"的素材。

## 完整流程

把四个工具放在同一个文件夹里，然后按顺序跑：

| 步骤 | 工具 | 输入 | 产出 |
|---|---|---|---|
| 1 | `crash-doctor.bat` | `.minecraft` 或崩溃日志 | `crash-diagnosis.txt` / `.json` |
| 2 | `java-doctor.bat` | `.minecraft` | `java-report.txt` / `.json` |
| 3 | `mod-check.bat` | `mods` 文件夹 | `mod-check-report.txt` / `.json` |
| 4 | `report-builder.bat` | 读上面三个 json | `诊断报告.html` |

第 4 步会问你两个可填可不填的问题：

- 客户称呼 → 印在报告抬头上
- 客户描述的现象 → 印在"问题现象"一节

不想填就直接回车跳过。

## 输出是什么

```
诊断报告.html
```

双击就能用浏览器打开，内容包含：

- 抬头：客户、日期、游戏目录、这次做了哪几项检查
- 四个数字卡片：确定的问题 / 需要留意 / 附带提示 / 检查正常
- 问题现象（你填的那句话）
- 诊断结论：按"确定 → 可能 → 提示"排序，每条标注来自哪个工具，带依据原文和处理步骤
- 环境信息表：游戏版本、Java 版本、内存、模组数量……
- 处理建议
- 说明与免责

它是**单个 HTML 文件，不依赖任何外部资源**，客户断网也能正常打开。

## 怎么发

三种都行：

1. **直接发 HTML 文件** —— 客户双击用浏览器打开（推荐）
2. **打印成 PDF** —— 浏览器里 Ctrl+P，"目标"选"另存为 PDF"
3. **截图** —— 发微信、QQ、群公告

报告有专门的打印样式，打印出来不会从中间截断卡片。

## 常见问题

**Q：提示"没找到任何诊断结果"？**
A：说明同目录下没有 json 文件。先按顺序把前三个工具跑一遍。注意 `report-builder` 和那三个工具要放在同一个文件夹里。

**Q：我只跑了其中一两个工具，能生成吗？**
A：能。有几份就合并几份，缺的部分不显示。但显然是跑全了报告更完整。

**Q：客户名写错了要重新跑一遍吗？**
A：不用重跑诊断，直接再运行一次 `report-builder` 就行 —— 它只是读 json 重新排版，很快。

**Q：报告里会不会泄露我的信息？**
A：报告里只有游戏目录路径、模组文件名这类东西，没有账号、没有聊天记录。发给客户前建议自己扫一眼。

**Q：客户那边是 Mac 怎么办？**
A：HTML 是通用的，任何浏览器都能开，不挑系统。

## 注意事项

- 报告里含客户机器的路径和模组清单，属于他的隐私信息，别随手发到公开场合（发之前把路径和模组名打码）。
- 想拿去做宣传素材的话，记得先征得客户同意。
- 报告是"诊断结论"，不是"包解决承诺"。措辞上别让客户误以为付了钱就一定百分百修好。
