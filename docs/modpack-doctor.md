# MC 整合包体检工具 使用说明

*modpack-doctor v3.1*

## 一、这个工具是干什么的

在启动游戏之前，检查 `mods` 文件夹里有没有会导致崩溃的问题，把问题提前找出来，省得反复开游戏试。

它不绑定任何整合包，Forge、Fabric、NeoForge 都能用，Minecraft 1.7.10 到 1.21 通用。

最有用的一条能力，是抓出"单个 mod 单独用都没事、放一起就崩"的元凶。这类问题通常是某个 mod 引用了不存在的接口，光看文件名或者崩溃截图基本查不出来。

## 二、运行条件

|  |  |
|---|---|
| 系统 | Windows 10 / 11，32 位和 64 位都行 |
| 软件 | 不需要另外装任何东西，PowerShell 是系统自带的 |
| 网络 | 不需要联网，全程只在你自己的电脑上读文件 |
| 权限 | 普通用户就行，不需要管理员权限 |

本工具只读取文件，不会修改、移动或删除 `mods` 文件夹里的任何内容。

## 三、怎么用

- 第 1 步  把压缩包解压到一个普通文件夹里（桌面就行，路径里有中文也没关系）。
  - 不要直接在压缩包里双击运行，一定要先解压出来。
  - `run-doctor.bat` 和 `modpack-doctor.ps1` 这两个文件必须待在同一个文件夹里，缺一个都跑不起来。
- 第 2 步  双击 `run-doctor.bat`
- 第 3 步  等它跑完。它会自动去找 `mods` 文件夹；找不到会提示你把 `mods` 文件夹拖到 `run-doctor.bat` 图标上松手，或者直接把完整路径粘进去回车。
- 第 4 步  跑完会在同一个文件夹里生成 `doctor-report.txt`。把这个 `txt` 文件发给我，我看完告诉你缺了什么、该怎么修。

深扫描大整合包要等一会儿。实测 70 个 mod、124 MB 的 1.20.1 整合包大约 90 秒，mod 越多越久。窗口没关就是还在跑。

## 四、找不到 mods 文件夹怎么办

按下面任意一种方式给它指路：

- 把 `mods` 文件夹直接拖到 `run-doctor.bat` 上松手
- 双击运行后，按提示把完整路径粘进去回车
- 把 `run-doctor.bat` 和 `modpack-doctor.ps1` 一起复制到整合包实例文件夹里再运行

它会自动尝试这些常见位置：

- 工具所在文件夹下的 `mods`
- `%APPDATA%\.minecraft\mods`
- 桌面各实例文件夹下的 `mods`
- `%USERPROFILE%\curseforge\minecraft\Instances\*` 下的 `mods`

## 五、报告怎么看

报告里的每一条问题都带严重程度：

- [错误]   基本一定会崩溃或功能失效，必须处理
- [警告]   很可能出问题，或者在特定条件下才发作，建议处理
- [提示]   仅供参考，可以忽略

报告最后有一行汇总，例如：

```
错误 2 项 / 警告 3 项
扫描了 70 个 jar（含 40 个内嵌 jar），用时 58.3 秒
```

"内嵌 jar"指的是 Forge JarJar 或者 Fabric 的嵌套依赖，很多现代 mod 自带，工具会一并检查，不用管它。

一个健康的整合包，最后应该是"错误 0 项"。警告里可能会有十几条，大多是没在元数据里声明的可选联动，核对一下没有真的缺前置就行。

## 六、它能查出哪些问题

- 1. 文件完整性
  - 抓 `jar` 打不开、空文件、以及只有几十字节的假文件。
  - 最常见的原因是下载时把 HTTP 错误页存成了文件。
  - 例：某个整合包里的 CodeChickenLib 只有 17 字节，内容是一句 "Moved Permanently"，导致 NEI 启动即崩。
- 2. 重复 class
  - 同一个类被多个顶层 `jar` 同时提供。
  - 例：包里同时存在两份 CodeChickenLib。
- 3. 重复 modid
  - 同一个 modid 被多个 `jar` 声明，游戏会直接崩。
- 4. 游戏版本混装
  - 比如 1.7.10 的包里混进了 1.12.2 或 1.8 的 mod。
- 5. 声明的前置缺失
  - `mods.toml`、`mcmod.info`、`fabric.mod.json` 里写明必需的前置没有装。
  - 内嵌 `jar` 里带的前置算已装。
- 6. 未声明的依赖引用
  - 最有价值的一项。某个 `class` 引用了 `mods` 里根本不存在的接口。
  - 例：GraviSuite 引用了 buildcraft 的 `IToolWrench`，但它没声明这个依赖，包里也没有 BuildCraft，于是游戏在加载 mod 阶段直接崩。
- 7. mod 摆放错误
  - `jar` 被放在了不会被扫描的子文件夹里。
  - 例：某文件被放在 `mods\ic2\` 下，而 Forge 只扫描 `mods\` 和 `mods\版本号\`。
- 8. 改名残留
  - `.jar.disabled`、`.jar.bak`、`xxx(1).jar` 这类文件，加载器有时仍会去读。
- 9. 官方校验（可选）
  - 如果给出 Modrinth 整合包文件（`.mrpack`），会逐个比对官方 SHA-1，找出被改动过和缺失的文件。

## 七、它查不出哪些问题

- 1. 第 6 项"未声明引用"是线索，不是判决。用反射或者 `isModLoaded` 保护过的软依赖会被列出来，属于误报。拿不准就把那一段发给我看。
- 2. 只查文件层面的问题。查不了 Java 版本不对、内存不足、显卡驱动、配置文件冲突、代码级 mixin 冲突、存档损坏。
- 3. CurseForge 的清单不含哈希，所以官方校验只能对 Modrinth 的 `mrpack` 做。
- 4. 内嵌 `jar` 之间的重复是正常的，JarJar 运行时会去重，所以重复 class 只统计顶层 `jar` 之间。
- 5. 判定"必需前置缺失"以 mod 自己的元数据声明为准。像上面 GraviSuite 那种用了别人的接口却不声明的，只能靠第 6 项发现。
- 6. 一个 `jar` 里到底有没有某个接口，是靠条目路径判断的，不需要真的运行游戏。

## 八、常见问题

### 问：双击 `run-doctor.bat` 一闪就没了

答：看是不是没解压，直接在压缩包里点了。必须先把压缩包解压出来再双击。另外确认 `run-doctor.bat` 和 `modpack-doctor.ps1` 在同一个文件夹里。

### 问：Windows 弹出"已保护你的电脑"蓝色提示

答：这是 SmartScreen 对来源未知的文件的常规提醒，不是报毒。点"更多信息"，再点"仍要运行"即可。

### 问：杀毒软件报可疑

答：本工具是文本脚本，做的是读取和解压 jar 文件的操作，某些杀软对这类行为敏感。加信任或者在杀软弹窗里选择"允许"即可。不放心可以先在记事本里打开这两个文件自己看一遍，内容全是明文，能读懂。

### 问：提示"禁止运行脚本"或者执行策略报错

答：用 `run-doctor.bat` 启动，它自带绕过参数，不要直接双击 `.ps1`。

### 问：报告打开是乱码

答：报告是 UTF-8 编码，用记事本或者 VS Code 打开。不要用老式的 GBK 编辑器。

### 问：跑得很慢

答：正常，深度扫描要逐个解压 jar 并解析 class。mod 特别多的话可以先等，或者告诉我，我给你跑快速模式的命令。

### 问：结果里几乎全是"找不到，可能缺失"

答：多半是路径指错了，指到了别的整合包的 `mods` 目录，清单自然对不上。

## 九、安全说明

- 只读取文件，不会修改、移动或删除 `mods` 里的任何内容
- 不联网，不会上传任何东西
- 不需要管理员权限
- 两个文件都是纯文本，可以用记事本打开自行检查

唯一会产生的文件是 `doctor-report.txt`，就是你发回来的那份报告。
